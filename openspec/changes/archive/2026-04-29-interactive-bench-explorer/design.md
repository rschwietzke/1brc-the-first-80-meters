## Context

To answer your question: No, this is much more than just navigation! While the UX focuses on "drilling down," it requires fundamental changes to how the backend aggregates data and how the frontend renders comparative visualizations.

Currently, the `benchmark-viewer` surfaces a flat list of `Measurement` entities using Lucene text searches. To provide a "Hierarchical Drill-down" experience (Test Run -> Variations -> Timeline -> Execution Detail), we need to dynamically reconstruct the hierarchy from the flat CSV data.

## Goals / Non-Goals

**Goals:**
- Dynamically group flat measurement data into "Test Runs" based on the execution `timestamp`.
- Introduce a faceted filtering sidebar to slice the hierarchy across dimensions (JDK, GC Options, Threads).
- Implement new ECharts components to visualize comparative data (e.g., bar chart diffs for Variations, line charts for Timelines).
- Use HTMX to load these different views dynamically without full page reloads.

**Non-Goals:**
- We will NOT change the structure of the input CSV files generated by the benchmark harness.
- We will NOT add multi-user authentication or cloud-sync features (this remains a local diagnostic tool).

## Decisions

1. **Test Run Aggregation via Timestamp**
   - *Decision:* We will group `Measurement` entities using their `timestamp` field to simulate a "Test Run" grouping.
   - *Rationale:* Since the benchmark harness executes a batch of tests simultaneously, they will share identical or near-identical timestamps. We can use Spring Data JPA aggregations or Hibernate Search terms to group these efficiently.

2. **UI Navigation Architecture**
   - *Decision:* We will introduce a Breadcrumb component and a Sidebar Facet component.
   - *Rationale:* The breadcrumbs allow the user to easily step backward up the hierarchy (Execution Detail -> Timeline -> Variations -> Test Run). The sidebar allows global filtering across any level.

3. **HTMX Dynamic View Swapping**
   - *Decision:* The `IndexController` will return different Thymeleaf fragments (`fragments/test-run`, `fragments/variations`, etc.) based on HTMX requests.
   - *Rationale:* This keeps the SPA-like feel without writing complex JavaScript routers. ECharts instances will be re-initialized when a new fragment is swapped in.

## Risks / Trade-offs

- **Risk: Timestamp Imprecision** -> If the benchmark harness takes hours to run, the timestamps for the first test and the last test in the same batch might differ.
  - *Mitigation:* We may need to round timestamps to the nearest hour/day or identify another correlation ID (like `vmOpts` + date) if pure timestamp grouping proves too fragmented.
- **Risk: Performance on Large Datasets** -> Grouping thousands of measurements on the fly might be slow.
  - *Mitigation:* Leverage Hibernate Search's faceted search aggregations, which use Lucene to group data exponentially faster than SQL `GROUP BY` operations.
